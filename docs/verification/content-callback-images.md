# Preserve existing editorial image output in content callbacks

Companion to existing API #438, compared with Tasks main `a01874b1c9db58f9cf19612a15df8b8162cd9545`. Existing createContentTask already returns imageUrl. The polling mapper currently forwards only videoSourceUrl and captionText, so the image is lost before sendContentCallback serializes results.

Add optional imageUrl to ContentRunResult and preserve a present imageUrl on completed results. Omitted/empty image values preserve the legacy serialized video-only shape; failed/rejected results do not gain image data. Keep run IDs, video/caption fields, run status handling,30-second polling, existing Promise.allSettled polling, retry and callback authentication/transport unchanged. No task/job, generation, provider request, paid step, UI, schedule, environment setting, dependency or SDK version is added. The modified mapper uses @trigger.dev/sdk root; installed4.3.3 maps root and /v3 to the same code.

The API companion must retain and post the image field. Recommend releasing the API receiver first. Without both sides, image delivery is not a completed user journey. Tests run actual polling mapper and callback serializer with mocked runs.poll and fetch using fixture callback URL/secret; they check per-run association, legacy omission, failed results and serialized image propagation. No real Trigger run, provider/Slack/customer/database/key/credit operation or secret inspection was performed. Source tests do not prove hosted callback/file delivery.

Release boundary: .github/workflows/deploy-trigger-prod.yml deploys on pushes to main. Opening this feature PR runs tests; merging it intentionally releases the existing worker code to Trigger.dev. Coordinator must account for that effect when approving the merge. No manual deployment, production workflow or new job is invoked here. Existing Tasks deprecation and all held audio/lipsync/provider/commercial/principal/SDKv7/original651 gates remain unchanged. Original API438 remains untouched.
